
The reason is that there's an **older mechanism** (`$C`) and a **newer mechanism** (`_tryEmitCUDASurfaceConvertCall`) that both deal with the same problem — format conversion for CUDA surface reads/writes — and they work at different levels.

**The `$C` mechanism (in slang-intrinsic-expand.cpp):** The intrinsic definition strings in hlsl.meta.slang contain `$C` placeholders (e.g., `surf2Dread$C<$T0>(...)`). When `IntrinsicExpandContext` encounters `$C`, it checks whether format conversion is needed and, if so, appends `_convert` to the function name. This delegates conversion to a CUDA prelude helper like `surf2Dread_convert<T>(...)`. The `$E` token similarly expands to the byte size of the backing element for byte-addressed coordinates.

**The `_tryEmitCUDASurfaceConvertCall` mechanism (in slang-emit-cuda.cpp):** This newer code intercepts the intrinsic *before* the `IntrinsicExpandContext` runs. It re-parses the same intrinsic definition string to detect whether it's a surface call (starts with `surf`, contains `$C`), then emits inline format conversion code (pack/unpack expressions in a lambda) instead of relying on prelude `_convert` helpers.

**Why the parsing is needed:** The emitter receives only the raw intrinsic definition string — it has no structured metadata saying "this is a surface read" or "this is a surface write" or "this intrinsic supports format conversion." The `$C` marker is the only signal embedded in the string, so `_parseCUDASurfaceIntrinsic` must string-parse it to decide whether to take over emission.

**How to avoid it:** You could introduce a dedicated IR instruction or decoration for surface access (e.g., `kIROp_CUDASurfaceRead` / `kIROp_CUDASurfaceWrite`) during IR lowering, carrying the resource, coordinates, format, and read/write intent as structured operands. The emitter would then match on the IR opcode directly in `tryEmitInstExprImpl` / `tryEmitInstStmtImpl` — no string parsing needed. Alternatively, you could add an `IRDecoration` on the intrinsic call site (or on the `__target_intrinsic` definition) that flags it as a surface operation with conversion support, so the emitter can check `inst->findDecoration<IRSurfaceConvertDecoration>()` instead of parsing the definition string. Either approach would move the "is this a surface call?" decision from emit-time string parsing to the IR level where it belongs.
